# Drex Dotz

> **Persistent autonomous AI workers with bounded capabilities.**  
> *Give agents jobs, not root access.*

[![License: Apache-2.0](https://img.shields.io/badge/License-Apache_2.0-blue.svg)](https://opensource.org/licenses/Apache-2.0)
[![Python 3.10+](https://img.shields.io/badge/python-3.10+-blue.svg)](https://www.python.org/downloads/)

**Drex Dotz** provides persistent, autonomous workers ("Dotz") that operate under a strict capability firewall. Instead of granting agents root access or unconstrained shell and filesystem permissions, every consequential action flows through the **Drex Agent Firewall**:

```text
Dot
→ capability request
→ Drex
→ ALLOW / BLOCK / bounded grant
→ execution
→ receipt
```

## Highlights

- **Open Source & Local-First**: Runs entirely on your local machine; zero external hosted infrastructure or cloud registry required.
- **Persistent Autonomous Workers**: Dots maintain local SQLite state, surviving process restarts and machine reboots.
- **Event & Schedule Wakeups**: Built-in cron/interval schedulers and idempotent event queues trigger autonomous workflows.
- **Bounded Drex Capabilities**: Hard invariants prevent workspace escapes, credential reading, and arbitrary shell execution. Consequential mutations require task-scoped, time-limited (`TTL`) grants.
- **Tamper-Evident Receipts**: Every evaluated action generates an immutable audit receipt with automated secret scrubbing.
- **Pluggable Model Routing**: Supports cost-aware model tiers (cheap local vs. frontier escalation).
- **Optional Integrations**: Seamless adapters for NousResearch Hermes Agent plugins and NOVA workflows.

## 5-Minute Walkthrough

### 1. Initialize Runtime Environment

Seed the runtime with the three standard example workers:

```bash
dotz init
```

Output:
```text
Initialized Drex Dotz runtime at ./dotz_runtime with 3 example Dotz.
```

### 2. List Registered Workers

```bash
dotz list
```

Output:
```text
DOT                  STATE        UPDATED             
-------------------------------------------------------
developer            IDLE         1760000000.0        
operator             IDLE         1760000000.0        
researcher           IDLE         1760000000.0        
```

### 3. Inspect the Researcher Dot

```bash
dotz show researcher
```

Output:
```text
Researcher status: IDLE

Workspace:
  ./dotz_runtime/dots/researcher/workspace

Model policy:
  default: cheap
  escalate: frontier

Capabilities:
  ✓ web.read
  ✓ files.read
  ✓ notes.write
  ✗ shell.execute
  ✗ secrets.read
  ✗ filesystem.modify
  ✗ money.spend
  ✗ filesystem outside workspace

Drex:
  enforcement active (pack: read-only-research)
```

### 4. Assign a Safe Research Task

```bash
dotz assign researcher "research latest security advisories and record notes" --exec
```

Output:
```text
Assigned task 'research latest security advisories and record notes' to Dot 'researcher' -> Task ID: task_c8f2b1
Executing task...
Result: Completed task
```

### 5. Inspect Receipts

Inspect the immutable audit trail generated by the capability firewall:

```bash
dotz history researcher
```

Output:
```text
ACTION          DECISION   CAPABILITY      TARGET                    RECEIPT_ID
--------------------------------------------------------------------------------
task_execute    ALLOW      research        notes                     rcpt_9f123a
```

### 6. Observe a Safe Drex BLOCK

When a Dot attempts an action outside its authorized capabilities—such as attempting shell execution or escaping its workspace—Drex immediately halts execution with **zero upstream side effects**:

```python
from dotz.runtime import Runtime

rt = Runtime()
task_id = rt.assign_task("researcher", "Attempt shell execution")

# Researcher attempts shell command without 'shell.execute' capability
result = rt.execute_dot_action(
    dot_name="researcher",
    task_id=task_id,
    capability="shell.execute",
    action="shell_execute",
    args={"command": "cat /etc/passwd"},
)

print(result)
# {'allowed': False, 'error': 'Capability shell.execute is denied by Dot policy', 'receipt_id': 'rcpt_...'}
```

The forbidden command is blocked before invocation, and a `BLOCK` receipt is recorded in the audit store.

## Public Examples Included

Drex Dotz ships with three bounded worker archetypes:

1. **Researcher** (`dotz/examples/researcher/`): Web research, reading local documentation, and compiling notes. Denied shell execution and destructive filesystem modification.
2. **Developer** (`dotz/examples/developer/`): Workspace code navigation and test execution. Consequential file edits require explicit, time-bounded mutation grants.
3. **Operator** (`dotz/examples/operator/`): Read-only log inspection and status checks without generic root access.

## Known Limitations

- **Process-Level Mediation**: Enforcement operates at the Python runtime and guarded adapter layer; it does not replace kernel cgroups or virtual machine sandboxing.
- **Local Persistence**: State is stored in local SQLite databases; cross-machine synchronization and cloud multi-tenancy are deferred to future milestones.
